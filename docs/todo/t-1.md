# Task: перевод Unity-клиента (virt-off) на V2 API сервера

Задача на завтра: научить толстого клиента работать с V2 API
(`virt-off-server --api v2`). Серверная часть уже готова и протестирована
(smoke + integration).

## Контекст — чем V2 отличается от V1 на проводе

Источник истины по байтам: `virt-off-server/src/net/ProtocolConstants.hpp` и
интеграционный клиент `virt-off-server/tests/integration/test_client.cpp`.

- `0xFF` — connect (client → server). Без изменений: один байт.
- `0xFE` — assign id (server → client).
  - **V1:** payload = `ulong` (8 байт, native-endian).
  - **V2:** payload = UTF-8 строка вида `player-<timestamp_ms>` (при коллизии в
    ту же миллисекунду — суффикс `-<n>`). Длина переменная, НЕ 8 байт.
- `0x01` voice и `0x02` position — сервер ТУПО релеит payload всем, кроме
  отправителя (не парсит и не трогает id). Значит id отправителя по-прежнему
  обязан лежать внутри пакета, и его кладёт сам клиент.

Следствие: в V1 клиент клал в пакет `id(8)` (ulong). Так как в V2 id — строка
переменной длины, нужно сменить формат кадра.

### Новый формат кадра для сообщений с id (V2)

Для `0x01`/`0x02` (а при желании и для `0x03`/`0x04`/`0x05`):

```
[type:1][idLen:1][id:idLen байт UTF-8][payload...]
```

`ASSIGN_ID` (0xFE) остаётся без префикса длины — весь остаток датаграммы есть
id: `[0xFE][id UTF-8...]` (так шлёт сервер, см. `v2/handlers/ConnectHandler.cpp`).

`idLen` — 1 байт (id заведомо < 256 байт: `player-` + 13 цифр + суффикс).

### Принятое по умолчанию решение (проверить/подтвердить)

- Клиент мигрирует **полностью на V2** (V1 больше не поддерживаем). Тогда
  сервер обязательно запускать с `--api v2`. Если нужна совместимость с V1 —
  добавить в `ServerConfig` поле версии и ветвить парсинг/запись id (см. п.11).
- Поля `ulong Id` во всех местах меняются на `string Id`.

## Общий помощник (сделать первым)

Добавить небольшой статический класс кодирования id, например
`Assets/Scripts/Net/IdCodec.cs`:

```csharp
using System.Text;

public static class IdCodec
{
    // Пишет idLen(1) + UTF-8(id) в buf начиная с offset, возвращает новый offset.
    public static int Write(byte[] buf, int offset, string id)
    {
        byte[] bytes = Encoding.UTF8.GetBytes(id);
        buf[offset] = (byte)bytes.Length;
        System.Array.Copy(bytes, 0, buf, offset + 1, bytes.Length);
        return offset + 1 + bytes.Length;
    }

    // Читает idLen(1) + id, возвращает строку, next = offset после id.
    public static string Read(byte[] buf, int offset, out int next)
    {
        int len = buf[offset];
        string id = Encoding.UTF8.GetString(buf, offset + 1, len);
        next = offset + 1 + len;
        return id;
    }

    // Устойчивый выбор модели аватара по строковому id (детерминированно в сессии).
    public static int StableIndex(string id, int count)
    {
        unchecked
        {
            int h = 17;
            foreach (char c in id) h = h * 31 + c;
            return (h & 0x7fffffff) % count;
        }
    }
}
```

## Риски / заметки
- **0x03/0x04/0x05 (удары, предметы, звуки) сервер не релеит** — в
  `src/app/Server.cpp` и `src/v2/app/Server.cpp` зарегистрированы только
  `0x01` и `0x02`. Без правок сервера эти фичи в мультиплеере работать не будут.
  Решение — отдельная серверная задача (добавить регистрацию/релей этих типов),
  требует ревью интерфейсов.
- `player-` в V2-id уже есть — не добавлять префикс повторно в нотификациях.
- Строковые словари — только `StringComparer.Ordinal` (id регистрозависим).
- `GetHashCode` между запусками не стабилен — для выбора модели использовать
  детерминированный хэш (`IdCodec.StableIndex`).
- Если id когда-нибудь превысит 255 байт — перейти на `idLen:2` (ushort).
